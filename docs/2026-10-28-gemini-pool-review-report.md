## 发布隐私

- 公开服务地址和精确网络白名单统一为保留占位域 cpa.example.invalid。公开包不是已经接通的私人部署。
- 使用前需同时替换 lib/gemini-quota.mjs 的服务常量和 manifest.json 的对应网络白名单。管理密钥仍只在 App 设置输入，不能写入源码。
- 发布通过 git archive 打包已提交源码，不包含 App 配置、运行数据、outputs 或内部工作记录。
- 旧公开文档中的具体现场用量、金额和会话标识在当前发布树中脱敏。不改写既有公开 Git 历史。
- 新提交和标签使用 GitHub noreply 身份，避免新增个人邮箱公开。

## 实现

- 看板侧栏与 Function Panel 复用同一紧凑卡片。未配置时整块隐藏。
- 设置提供 CPA 管理密钥输入、保存和清空。密钥不回填，不写浏览器存储。
- 后端通过 CPA v8 账号列表与受控 api-call 查询 Antigravity 分组配额。固定主机与配额目标，不跟随管理请求重定向，不下载 OAuth 凭据。
- 只返回脱敏账号、健康状态、配额查询状态、分组剩余比例和重置时间。0 有效，失败不是 0，过期只显示待刷新。
- 管理密钥仅存 App dataDir，文件权限 0600。完整邮箱、账号索引、项目标识、路径和原始错误不送前端。

## 性能与安全取舍

1. 使用现有原生 JavaScript 和 SDK，不加依赖。代价是只覆盖当前固定 CPA v8 契约，不自动兼容未知旧部署。
2. 保留 Antigravity 共享 groups/buckets，不聚合账号百分比。代价是不提供看似直观但无依据的“总池百分比”。
3. 一般结果缓存 60 秒，双端和手动刷新共享在途任务。代价是手动刷新不保证立即绕过缓存。
4. 每轮最多 3 账号并发；12 秒总预算包含账号列表和响应体，单请求最多 8 秒。代价是较慢或较大的池可能只有部分账号完成，其余明确标超时。
5. 管理鉴权外层 401/403 暂停重试，防止连续失败封 IP。代价是外部权限修好后也需重新保存配置。内层账号 401 不触发此暂停。
6. 缺项目标识不下载凭据补齐。代价是这些账号无法查询，而不是伪造额度。
7. 在当前目录的功能分支完成开发，不额外复制 worktree。发布采用普通提交和快进整合，不删除目录或改写历史。

## 未验与非阻断边界

- 代理未读取真实 CPA 密钥或真实配额。匿名 401 不能证明 v8 路径已可用；用户本机试装反馈不等同于代理独立鉴权验收。
- 要测试公开构建，先替换占位地址及白名单，再安装并在设置输入管理密钥。不在聊天里索取明文。
- Minor：只有 BroadcastChannel 不可用、父窗口不转发，且两次保存恰好同毫秒时，备用 storage tick 可能相同。正常广播不受影响。按用户避免过度防御的要求，未添加随机数或计数器。
